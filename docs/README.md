# Документация проекта

## 1. Назначение документации
Данная документация предназначена для разработчиков, администраторов системы и конечных пользователей. Она содержит технические спецификации, руководства по использованию API, инструкции по развёртыванию и правила внесения изменений.

## 2. Структура каталога
Основные разделы документации:

```
docs/
├── guides/           # Практические руководства
├── api-reference/    # Спецификации API
├── tutorials/        # Пошаговые обучающие материалы
├── images/           # Графические материалы
└── README.md         # Этот файл (обзор документации)
```

## 3. Локальная настройка
Для предпросмотра документации локально:

**MkDocs:**
```bash
pip install mkdocs
mkdocs serve
```

**Docusaurus:**
```bash
npx create-docusaurus@latest my-docs classic
cd my-docs
npm start
```

**Sphinx:**
```bash
pip install sphinx
sphinx-quickstart
make html
```

## 4. Правила оформления
- Используйте Markdown-синтаксис
- Имена файлов: в нижнем регистре с дефисами (`getting-started.md`)
- Изображения: только в форматах PNG/JPEG/SVG, размещать в `/images`
- Заголовки: использовать структуру H2-H4
- Код: оборачивать в блоки с указанием языка (```javascript)

## 5. Публикация
Процесс деплоя документации:

1. Сборка статического сайта:
```bash
mkdocs build  # Для MkDocs
npm run build # Для Docusaurus
```

2. Публикация на:
- GitHub Pages: через Actions
- Netlify: через автоматический деплой из ветки `gh-pages`

## 6. Контрибуция
Порядок внесения изменений:
1. Создать Issue с описанием проблемы/улучшения
2. Форкнуть репозиторий и создать ветку для правок
3. Добавить изменения с соблюдением правил оформления
4. Открыть Pull Request с описанием изменений
